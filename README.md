# Atoms Demo

一个可部署的自然语言应用生成器。输入一句话，智能体生成应用规格，服务端将规格编译成独立 HTML，执行交互检查。通过后可打开、分享或下载产物。首页直接提供三个成品，游客可生成和试用，注册登录后可恢复自己的记录。

## 本地启动

使用 Docker Compose 时，在当前终端设置 `POSTGRES_PASSWORD` 后启动应用与 PostgreSQL 16。

```bash
docker compose up -d --build --wait
```

也可使用 Node.js 24、npm 和独立 PostgreSQL 数据库。先设置 `DATABASE_URL` 为该数据库的连接 URL。

```bash
npm ci
HOST=127.0.0.1 npm start
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。无模型配置时，应用会使用匹配的内置模板，结果标为「演示模式」。服务器首次启动会运行三项种子成品的检查并存入数据库。

设置 `TEST_DATABASE_URL` 指向专用 PostgreSQL 测试数据库，再运行 `npm test`。测试为每个用例创建独立 schema，覆盖验证码注册、密码登录、分享链接、模型接口接线及降级情况。模型接口测试使用本地模拟服务。

## 评审操作

| 输入或操作 | 预期 |
|---|---|
| 注册 | 输入用户名和至少 8 字符的密码，按提示点击验证码图片中的图案。 |
| 退出后登录 | 只输入用户名和密码，工作台可找回该账号的历史。 |
| 做一个窗帘预算计算器，输入窗宽、褶皱倍数和每米价格，输出预算 | 自动检查通过后打开应用链接。输入 3、2、100 得到 600 元。清空字段时显示提示。 |
| 做一个 2048 小游戏，简单说明游戏规则 | 打开原创 5×5 数字合成游戏，查看规则，用方向键或屏幕按钮操作，可重新开局。 |
| 做一个秒表 | 打开产物链接，依次操作开始、暂停、继续和归零。 |
| 给刚才这个秒表增加计次功能，保留现有操作 | 测试通过后生成新链接。开始计时后点击「计次」会记录当前累计时间。「查看上一版」可恢复原有链接。 |

每次提交会在工作台显示生成进度，进行中的生成可以取消。点击「自动测试」查看实际执行结果。测试通过后出现「打开应用」「复制链接」「下载 HTML」。分享链接指向本次已保存版本，访客可以直接打开。当前支持给秒表添加计次，修改失败时仍可操作已保存版本。

## 实现与取舍

- **运行方式**：一个 Node.js 进程提供静态前端、生成接口和分享路由。PostgreSQL 16 存储账号、会话和已通过检查的产物。
- **生成方式**：模型输出结构化 JSON。校验应用类型、字段和公式后，用可信的运行时代码编译为独立 HTML。适用范围是数值计算器、数字合成游戏和秒表。
- **失败处理**：上游限流和暂时不可用时有限重试。无 Key、请求失败或模型产物校验不通过时，匹配到的内置模板可继续生成和测试。
- **验收方式**：服务端在 DOM 环境运行产物，操作表单、按钮、键盘等入口，核对结果。秒表使用受控时钟。公网交付前验证真实浏览器和 HTTPS 地址。
- **账号方式**：用户名、scrypt 密码哈希、持久化会话和一次性图像选择验证码。当前验证码为简化版图形验证。

## 部署与 GitHub

GitHub 提供代码仓库。公网运行需要 Docker 或 Node.js 主机和可访问的 HTTPS 地址。Compose 在容器内网连接 PostgreSQL，数据库数据保存在 `postgres_data` 命名卷。应用端口默认绑定回环地址，部署时通过 HTTPS 反向代理访问。

| 运行环境变量 | 用途 |
|---|---|
| `PORT` | HTTP 端口，默认 `3000`。 |
| `HOST` | 监听地址，容器默认 `0.0.0.0`。 |
| `DATABASE_URL` | 手动启动 Node 时使用 PostgreSQL 连接 URL。也可使用标准 `PGHOST`、`PGUSER`、`PGDATABASE`、`PGPASSWORD` 配置。 |
| `POSTGRES_PASSWORD` | Compose 读取的数据库密码，从终端环境或部署平台密钥配置传入。 |
| `PUBLIC_ORIGIN` | 客户端访问的完整 HTTPS origin，用于校验请求源和设置 Secure Cookie。 |
| `LLM_BASE_URL` | 兼容 Chat Completions 的服务地址，填写到 `/chat/completions` 之前。 |
| `LLM_MODEL` | 模型服务商提供的模型名。 |
| `LLM_API_KEY` | 在服务器的密钥配置中设置。 |

在已有 HTTPS 反向代理后绑定服务端口，向应用传递客户端请求的 Host。部署后用国内手机流量和无痕窗口分别检查首页、账号流程及三个分享链接。检查持久卷在服务重启后能恢复生成记录。
